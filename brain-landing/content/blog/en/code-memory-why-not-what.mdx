Point a coding agent at your repo and it can read every line. Ask it *why* a
particular line exists and it's stuck — because the answer was never in the code.
It was in a commit message that scrolled away, a review comment, a Slack thread,
someone's head. The code is the *what*. The expensive, easily-lost part is the
*why*.

## Indexing the repo is the wrong layer

The reflex is RAG-over-repo: embed the source, retrieve similar snippets. That's
a fine code *search*. It's a useless *memory*, because the thing you keep
re-learning isn't the code — the agent can read that — it's the reasoning that
produced it:

- **Decisions** — "we funnel all token checks through one guard."
- **Rationale** — "because three middlewares had drifted and disagreed on
  expiry."
- **Invariants** — "every migration must be idempotent."
- **Gotchas** — "SCHEMAFULL rejects a JS null for `option<>` — emit NONE."

None of that is recoverable from the diff. Re-indexing the source a thousand
times will never surface it, because it isn't there.

## Capture the why, gate out the noise

Most commits carry no decision — `bump deps`, `run prettier`, `fix typo`. If you
store all of them you bury the signal. So capture is **gated**: a layered
classifier decides whether a change actually carries a decision, rationale,
invariant, or gotcha before anything is written, and only the reasoning-bearing
ones become memory. The cheap heuristic catches the obvious cases; a trained
gate handles the ones where the reason hides in the subject line. The result is
a memory that's dense with *why* and light on noise.

And it runs where the code does. Classification and extraction happen
client-side; only the finished note, a symbol anchor, and provenance travel to
the store. Raw source never leaves the machine.

## Anchor to symbols, not line numbers

Here's what kills most code-adjacent notes: they're pinned to a file and a line,
and the first `git pull` or formatter run moves the line out from under them. A
week later the note points at the wrong code, which is worse than no note.

Code memory anchors to a **symbol path** —
`FactResolverService.resolve`, not `file.ts:184`. Reformat the file, move the
function, shift a hundred lines: the anchor still resolves. When a symbol
genuinely disappears, a re-validation sweep tries to re-anchor it to its renamed
match — `resolv` → `resolve` — and only retires the note if there's no plausible
one. A blast-radius guard refuses to mass-invalidate when a sweep is
misconfigured, so a run from the wrong directory can't wipe your notes.

## Why it compounds

Every decision an agent captures makes the next one cheaper. The next time it
touches that guard, the reason it exists is right there — anchored to the guard,
not lost in history. Give your agent a memory for *why*, and it stops re-deriving
the same conclusions, or worse, undoing them.

The code says what. Code memory says why — and keeps saying it after the
refactor.
