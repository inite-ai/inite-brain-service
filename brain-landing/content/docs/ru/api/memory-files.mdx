# Файлы памяти

Память в форме файлов: собственные заметки модели по путям под
`/memories`, лежащие в базе тенанта за теми же фенсами, что и вся
остальная память.

Это существует по одной причине. Memory tool от Anthropic
(`memory_20250818`) даёт модели файловую систему, которой она владеет —
`view`, `create`, `str_replace`, `insert`, `delete`, `rename`, — а
хранилище оставляет разработчику. Все референсные реализации пишут в
локальный каталог, который забывает всё при редеплое, невидим для любой
другой поверхности и принадлежит тому контейнеру, которому повезло
обработать запрос. Эти роуты — альтернатива, а
[`@inite/brain-memory-tool`](https://www.npmjs.com/package/@inite/brain-memory-tool)
— адаптер, который говорит с ними на языке команд этого инструмента.

## Роуты

| Роут | Scope | Что делает |
| --- | --- | --- |
| `PUT /v1/memory-files` | `brain:write` | Создать или заменить `{ path, content }` |
| `POST /v1/memory-files/read` | `brain:read` | Один файл или 404 |
| `POST /v1/memory-files/list` | `brain:read` | Пути под `{ prefix }`, в порядке пути, до 1000 |
| `POST /v1/memory-files/rename` | `brain:write` | Перенести `{ path → newPath }` |
| `POST /v1/memory-files/delete` | `brain:write` | Удалить файл или каталог со всем содержимым |

```bash
curl -X PUT "$BRAIN_URL/v1/memory-files" \
  -H "Authorization: Bearer $BRAIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "path": "/memories/user_prefs.md", "content": "- предпочитает табы\n- релизит по пятницам" }'

curl -X POST "$BRAIN_URL/v1/memory-files/read" \
  -H "Authorization: Bearer $BRAIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "path": "/memories/user_prefs.md" }'
```

## Решения, которые заметны

**Путь едет в теле, в том числе на чтениях.** В путях есть слэши, а путь
в URL означает, что `/memories/a%2Fb` и `/memories/a/b` могут разойтись
в идентичности. При фенсе строки по `(path, userId)` это вопрос контроля
доступа, а не косметики.

**Содержимое хранится дословно.** Ни обрезки, ни переносов, ни
нормализации концов строк. `str_replace` — строковая операция ровно над
этими байтами, поэтому любая «уборка» испортила бы собственные заметки
модели так, что это выглядело бы как галлюцинация.

**Роутов `str_replace` и `insert` нет.** Это read-modify-write над точным
текстом, и сервер, владеющий такой merge-политикой, — это сервер,
угадывающий намерение модели. Адаптер делает их над тем, что вернул
`read`.

**`userId` — настоящий фенс, а не соглашение о префиксах.** Два человека
с одним ключом воркспейса получают разные файлы по одному пути и не
видят чужой — в том числе в `list`. Без `userId` адресуется
общий файл воркспейса, и это **другая строка**, чем персональный файл по
тому же пути. Так задумано: альтернатива — молча затирать чужие заметки.

**Пространство путей закрыто.** Всё, что не начинается с `/memories/`,
всё с `..`, `//` или нулевым байтом, и `/memoriesevil.md` — который
начинается с корня, но не лежит внутри него, — это `400`.

**Удаление каталога рекурсивно и возвращает счётчик.** `delete` на
`/memories/tmp` сносит всё под ним и отвечает `{ "deleted": 4 }`.

## Без версий

Последняя запись по пути побеждает — ровно семантика самого memory tool.
Модель, правящая файл двадцать раз за сессию, иначе оставила бы двадцать
ревизий, которые никто не читает. История, которая имеет значение, живёт
в таймлайне фактов, а он битемпоральный по-настоящему — см.
[битемпоральность](/ru/docs/concepts/bitemporal).
