# POST /v1/search

Гибридный retrieval по графу знаний на тенанта. Vector + BM25 + опциональный HyPE → выпуклая свёртка → буст роутера предикатов → опциональный cross-encoder → listwise LLM-rerank с self-consistency → дозагрузка фактов сущности.

## Запрос

```http
POST /v1/search
Authorization: Bearer <api-key>
Content-Type: application/json
```

```ts
{
  query: string                    // natural language, ≤ 8 000 chars
  limit?: number                   // 1..100, default 10
  predicates?: string[]            // optional filter — restrict to these predicates
  entityTypes?: string[]           // restrict to these entity types
  entityIds?: string[]             // anchor on known entities (multi-hop chaining)
  asOf?: string                    // ISO 8601 — historical cutoff
  minConfidence?: number           // 0..1 — drop facts below this raw confidence
  includeContested?: boolean       // include COMPETING facts
  includeStale?: boolean           // ignore validity windows (audit shape)
  includeRetracted?: boolean       // include retracted rows too
  searchMode?: 'vector' | 'lexical' | 'hybrid'  // retrieval strategy, default hybrid
  userId?: string                  // per-user memory scope (tenant-global + this user)

  // Agent primitives (KnowQL-style)
  confidenceFloor?: number         // 0..1 — floor AFTER decay × source-trust weighting
  requireProvenance?: boolean      // drop facts without a source trail
  tokenBudget?: number             // 50..50000 — cap response size, tiktoken-exact
  outputShape?: 'full' | 'compact' | 'ids'  // response verbosity
}
```

Пояснения к полям:

- **`searchMode`** — `hybrid` (по умолчанию) сводит vector + BM25 через
  reciprocal-rank fusion; `vector` — только эмбеддинги (парафразы,
  кросс-языковые запросы); `lexical` — только BM25 (точное совпадение
  токенов: идентификаторы, регуляторные тексты).
- **`userId`** — per-user scope памяти: в результатах общие факты тенанта
  плюс личные факты этого пользователя; без поля — только общие (fail-closed).
- **`confidenceFloor`** — строже, чем `minConfidence`: применяется после
  decay и взвешивания по доверию к источнику. Агентам, которым нельзя шуметь,
  стоит ставить ≥ 0.5.
- **`requireProvenance`** — каждый возвращённый факт обязан нести непустой
  объект `source`; нужно compliance-потокам с цитированием источника.
- **`tokenBudget`** — сервер выбрасывает сущности с наименьшим score, пока
  сериализованный ответ не влезет; считается tiktoken-энкодингом
  `cl100k_base` — тем же, каким тарифицирует LLM.
- **`outputShape`** — `full` (сущности + факты + score), `compact` (по одному
  топ-факту на сущность, без score), `ids` (только id сущностей — дешевле всего).
- **`entityIds`** — ограничить факты владельцами из списка; hop N в multi-hop
  цепочке якорится на id, которые выдал hop N-1.

## Ответ

```ts
{
  hits: Array<{
    entity: {
      id: string
      name: string
      type: string
      externalRefs: Array<{ vertical: string, id: string }>
    }
    facts: Array<{
      factId: string
      predicate: string
      object: string | null  // null when PII-gated
      validFrom: string
      validUntil: string | null
      confidence: number
      status: 'active' | 'superseded' | 'retracted'
      sourceVertical?: string
    }>
    score: number          // post-rerank fused score
    legScores: {           // per-leg contribution; useful for debugging
      vector?: number
      lexical?: number
      hype?: number
    }
  }>
  diagnostics?: {
    router?: { predicates: Record<string, number>, types: Record<string, number> }
    rerank?: { invoked: boolean, n: number, skippedReason?: string }
    cacheHit?: boolean
  }
}
```

## Стадии пайплайна

Пайплайн отрабатывает за один HTTP-вызов. Каждая стадия — фичефлаг на уровне сервиса; оператор переключает их на тенанта.

**Граф — в основе, вектор — только дверь.** Единица поиска — типизированный факт на графе знаний, а не текстовый чанк. Векторная и BM25-ноги решают ровно одну задачу: превратить свободный текст запроса в кандидатов-фактов (из естественного языка нужен *какой-то* вход в граф). Всё дальше — нативно графовое: роутер работает по онтологии предикатов, кандидаты группируются по сущностям, edge expansion и PPR — буквальные обходы графа, а битемпоральная отсечка и множители trust/corroboration — это семантика самого графа. Запросы с именованными якорями входят в граф напрямую, минуя двери: `graph_retrieve` (сущности → окрестность в один шаг) и multi-hop планировщик, а чтение профилей и таймлайнов вообще не касается векторов.

```
                   query
                     │
                     ▼
       ┌─────────────────────────────┐
       │ predicate + type router     │  joint LLM call → soft distribution
       │ (LRU-cached per query hash) │
       └─────────────────────────────┘
                     │
       ┌─────────────┼─────────────┐
       ▼             ▼             ▼
  vector leg   lexical leg   (HyPE alt-emb leg)
  (HNSW cos)   (BM25)        max(cos_main, cos_alt)
       │             │             │
       └─────────────┼─────────────┘
                     ▼
       convex-fusion (CombMNZ-flavoured w=0.5)
                     │
                     ▼
       decay × confidence × predicate-boost-α
                     │
                     ▼
       group-by-entity ──→  PPR prior (HippoRAG, opt-in)
                     │
                     ▼
       cross-encoder (Cohere Rerank v3.5, opt-in)
                     │
                     ▼
       listwise LLM reranker (RankGPT-style + self-consistency)
                     │
                     ▼
       entity-fact backfill (native Surreal inline subquery)
                     │
                     ▼
                  results
```

## Битемпоральная отсечка

`asOf` уходит прямо в WHERE на уровне этапа:

```sql
WHERE validFrom <= $asOf
  AND (validUntil IS NULL OR validUntil > $asOf)
  AND (retractedAt IS NULL OR retractedAt > $asOf)
```

Никакого пост-фильтра на JS, никакого второго round-trip.

## Гейтинг PII

Если у API-ключа вызывающего нет `brain:read_pii`, чувствительные предикаты (`email`, `phone`, `dob`, `address`) приходят с `object: null`. Сам предикат остаётся видимым — это сигнал «данные у нас есть, прав у тебя нет». Это строже, чем 403, потому что ранжировать сущности по *наличию* идентифицирующих фактов всё ещё можно.

## CI по каждому этапу

Каждый релиз гоняет `pnpm test:eval`, который бутстрапит 95% CI по recall@1, MRR, NDCG@10 для каждого этапа. Числа пишутся в `.eval-baseline/main.json`. Просадка больше 3 п.п. = блок CI.
