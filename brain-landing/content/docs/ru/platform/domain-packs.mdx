# Domain Packs

**Domain Pack** — версионируемый подключаемый бандл онтологии, расширяющий реестр предикатов Brain **без форка ядра**. Домен — недвижимость, финтех, комплаенс, ваш собственный — поставляет свои типизированные предикаты плюс, опционально, тюнинг экстракции, eval-фикстуры, исполнение индексера, seed-документы и MCP-инструменты. Комьюнити-пак — это просто JSON: без PR в репозиторий Brain, публикация в реестр, установка на тенанта.

## Манифест — шесть секций

Пак — это один подписанный JSON-манифест с checksum. Каждая опциональная секция покрыта checksum'ом — «внеофициального» содержимого у пака не бывает:

| Секция | Что делает |
| --- | --- |
| `predicates` | Онтология: `localId`, тип данных, семантика (`single_active` / `append_only` / `bitemporal`), период полураспада decay, PII-класс, опциональный `requiresScope`. Хранится в неймспейсе `<packId>__<localId>` — двойное подчёркивание зарезервировано как разделитель, и загрузчик роняет старт при любой коллизии с ядром или другим паком. |
| `extractionProfile` | Тюнинг экстрактора, потребляется при извлечении: доменная `guidance` дописывается к системному промпту + `fewShot`-примеры (рендерятся как иллюстративный текст — сломать строгую схему вывода они не могут). |
| `evalFixtures` | Экстракционные тесты пака. `POST /v1/admin/packs/:id/eval` прогоняет каждую фикстуру через ЖИВОЙ экстрактор и отдаёт pass / fail — сначала измерь, потом доверяй. |
| `indexer` | Как пак участвует в [пайплайне документов](/ru/docs/platform/document-pipeline): `virtual` (едет в общем union-вызове экстракции, ноль лишних LLM-затрат), `dedicated` (собственный прогон экстракции, гейтится роутером релевантности) или `external` (удалённый индексер стейджит кандидатов). |
| `seedDocuments` | Знание, поставляемое вместе с паком — до 32 документов (≤ 65 536 символов каждый), которые при установке проходят через обычный пайплайн документов: тот же чанкинг, разрешение конфликтов и провенанс, что у документа любого коннектора. На каждом производном факте — provenance-мета (`pack_id`, `pack_version`, …). |
| `mcpTools` | До 8 инструментов, добавляемых на MCP-поверхность тенанта после явного согласия оператора — см. [справочник MCP-инструментов](/ru/docs/mcp/tools). |

## Цикл автора

```bash
pnpm pack:init my_pack               # скаффолд валидного стартового манифеста
# правишь my_pack.pack.json — предикаты, профиль, фикстуры…
pnpm pack:validate my_pack.pack.json # проверка стандарта + коллизий с ядром
pnpm pack:sign -- --file my_pack.pack.json --key priv.pem --publisher acme  # ed25519
pnpm pack:publish -- --brain-url https://brain.inite.ai \
  --file my_pack.pack.json --verify  # нужен registry:publish
pnpm pack:install -- --brain-url https://brain.inite.ai \
  --registry my_pack                 # нужен brain:admin, пин по checksum
```

Целостность сквозная: каждая установка сохраняет sha256 `packChecksum` (передай `--verify` — и сервер отклонит несовпадение: «ставлю ровно тот манифест, который ревьюил»), а ed25519-`signature` + `publisher` доказывают авторство против trust store тенанта (`DOMAIN_PACK_TRUSTED_KEYS`; `DOMAIN_PACK_REQUIRE_SIGNATURE=true` делает подпись обязательной).

## Реестр

Паки публикуются в **глобальный реестр** — общий, не привязанный к тенантам каталог с инвариантами в духе npm/crates.io:

- **Неизменяемость версий** — `(packId, version)` адресуется содержимым; переопубликовать другую начинку под тем же номером — `409`.
- **Yank, а не удаление** — плохая версия выпадает из resolve-latest, но запиненные установки остаются воспроизводимыми.
- **Verified-бейджи** — пак, чья подпись проходит проверку против trust store инстанса, помечается verified; профиль издателя может писать только компания с ≥ 1 verified-паком под этим publisher id (сквоттинг известного имени не пройдёт).
- **Счётчики скачиваний** — установки из реестра инкрементируют счётчик (отклонённая установка скачиванием не считается).
- **Зеркалирование** — задай `REGISTRY_UPSTREAM_URL`, и фоновая джоба pull-зеркалирует каталог другого инстанса через обычный путь публикации (валидация, неизменяемость и локальная пере-проверка доверия применяются; локальные строки всегда важнее).

Поиск — `brain:read` (`GET /v1/registry/packs`), публикация — `registry:publish`, установка на тенанта — `brain:admin`, а `GET /registry/ui` — публичный HTML-каталог.

## Маркетплейс

Реестр по совместительству маркетплейс, всё состояние локально для инстанса: **кураторство featured** (`registry:curate` переключает флаг; featured-паки поднимаются в топ каталога), **профили издателей** (публичные страницы по publisher id) и **платные паки**. Цена задаётся на уровне реестра на пак: издатель делает `PUT` цены, что создаёт billing-продукт с энтайтлментом **`domain_pack:<packId>`**. Флоу установки для неоплатившего тенанта:

```
POST /v1/admin/packs/from-registry {packId}   → 402 + самоописывающий указатель на checkout
POST /v1/admin/registry/packs/:id/checkout    → { checkoutUrl } — открыть, оплатить
POST /v1/admin/packs/from-registry {packId}   → ставится
```

Поза fail-closed: энтайтлменты опрашиваются у billing-сервиса через короткий TTL-кэш, который никогда не отдаётся протухшим. При выключенном `DOMAIN_PACK_BILLING_ENABLED` — а это дефолт и поза self-hosted — платные метаданные игнорируются и **каждый пак ставится бесплатно**. Цена и кураторство живут вне подписанного манифеста, так что переоценка не ломает подписи.

## Библиотека паков первой стороны

Помимо встроенного `code_memory` (инженерное «почему» кодовой базы), Brain поставляет шесть distributable-паков по индустриям — `real_estate`, `fintech`, `medical`, `legal`, `insurance`, `hr` — каждый с полной онтологией: предикаты, extraction-профиль и eval-фикстуры.
