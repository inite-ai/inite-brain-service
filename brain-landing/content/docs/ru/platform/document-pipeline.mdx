# Пайплайн документов

Как целые документы становятся памятью: **Source → Indexer → Candidates → Brain**. Пайплайн разрезает ингест на четыре слоя с намеренно жёсткими границами — экстракция ПРЕДЛАГАЕТ, а РЕШАЕТ ровно один движок. Вся поверхность поставляется тёмной за `DOCUMENT_INGEST_ENABLED` (по умолчанию выключено); с выключенным флагом классические пути mention / fact работают байт-в-байт как раньше.

## Четыре слоя

1. **Source** — коннекторы разбираются с сырыми форматами (PDF, почта, чаты, git); через API проходит нормализованный документ. Идентичность — это содержимое: `contentHash` (sha256 отредактированного текста) уникален, повторная отправка того же документа дедупится на входе. PII вычищается до хеширования, затем текст нарезается на чанки для экстрактора.
2. **Indexer** — доменный «читатель», объявленный в манифесте Domain Pack. Три режима исполнения: `virtual` (едет в едином union-вызове экстракции — ноль лишних LLM-затрат), `dedicated` (собственный прогон по отфильтрованному под пак словарю, гейтится на документ роутером релевантности), `external` (удалённый сервис читает документ и стейджит кандидатов — см. [внешние индексеры](/ru/docs/platform/external-indexers)).
3. **Candidates** — выход индексера стейджится по строке на сущность / факт / связь, с полным провенансом. Это ещё не память: `pending → committed | merged | rejected | expired`.
4. **Brain (коммит)** — унифицирует сущности между прогонами, сливает дубли фактов (confidence берётся как максимум, никогда noisy-or — два читателя одного документа не независимые свидетельства) и гонит всё через тот же `fn::resolve_fact`, что и любой другой путь записи. Второго решающего движка нет.

## Ингест документа

`occurredAt` (собственные часы документа — станут `validFrom` фактов) и `contextRef.vertical` обязательны:

```bash
curl -X POST "$BRAIN_URL/v1/ingest/document" \
  -H "Authorization: Bearer $BRAIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "kind": "markdown",
    "text": "…нормализованный текст документа…",
    "title": "Q2 support review",
    "originUri": "https://intranet/notes/q2",
    "occurredAt": "2026-07-01T10:00:00Z",
    "contextRef": { "vertical": "support" },
    "storeContent": true
  }'
```

Нужен `brain:write`. Текст ограничен 512 K символов; `mode: 'sync' | 'async'` выбирает между инлайн-прогоном и очередью джобов.

### Ручка приватности `storeContent`

`storeContent: false` оставляет только заголовок + хеш: экстракция всё равно отработает из тела запроса, но переиндексировать документ или пере-проверить span'ы позже уже нельзя — это явный размен на приватность. `DELETE /v1/documents/:id/content` вычищает сохранённые чанки постфактум, а факты, закоммиченные из вычищенного документа, получают штамп `provenancePurged: true` — им по-прежнему верят, но их можно отличить.

## Корроборация по origin-ключу

Независимость определяется **документом-источником**, а не читателем. Два индексера над одной расшифровкой встречи никогда не «независимо подтвердят» друг друга — тот же документ значит refresh, а не корроборацию. Разные документы, даже через один коннектор, — независимые свидетельства (`CORROBORATED`, вливаются в fact trust на чтении).

## Переиндексация

Ради этого и хранится нормализованный текст: поставь или обнови пак — и прогони его экстракцию по уже сохранённым документам тенанта: `POST /v1/admin/documents/reindex` (`brain:admin`) или автоматически с `REINDEX_ON_PACK_INSTALL=1`. Реестр прогонов (UNIQUE по документ × пак × версия) пропускает всё, что версия пака уже обработала; новые кандидаты сливаются с существующей памятью через тот же резолвер.
