# Хуки жизненного цикла

Набор инструментов помнит только тогда, когда модель решит их позвать. На практике модели почти никогда не зовут `record_fact` сами — и это самая частая причина, по которой интеграция памяти кажется мёртвой: всё подключено правильно, но не записывается ничего.

Хуки убирают это решение из модели. Харнес выдаёт событие — сессия началась, контекст вот-вот схлопнут, сессия закончилась — и маленький скрипт читает из brain или пишет в него независимо от настроения модели.

Почти всю ценность дают два события:

| Момент | Что делать | Почему именно там |
|---|---|---|
| **Старт сессии** | Поискать в brain по проекту и подложить результат | Единственная точка, где контекст бесплатен — до первого токена разговора |
| **Перед компактификацией / в конце сессии** | Отправить человеческие реплики в `/v1/ingest/mention` | Последний момент, когда сессия ещё существует целиком |

## Claude Code

[Плагин](https://github.com/inite-ai/inite-brain-service/tree/main/plugins/inite-brain) везёт оба, собранные и покрытые тестами:

```
/plugin marketplace add inite-ai/inite-brain-service
/plugin install inite-brain@inite
```

`SessionStart` → recall, `PreCompact` + `SessionEnd` → capture. Оба — переключатели в настройках плагина, по умолчанию включены.

### Что именно уходит в capture

Твои сообщения, и никогда — вывод модели. Скармливать текст ассистента обратно как запомненный факт — это то, чем слои памяти сами себя отравляют: пересказ модели о том, что она сделала, завтра становится «фактом» о том, как есть. А намерение, которое стоит помнить (что попросили и зачем), и так живёт на твоей стороне разговора.

Текст уходит в `POST /v1/ingest/mention`, так что экстрактор brain превращает его в факты и сохраняет исходную реплику как эпизод за ними. Любой факт остаётся прослеживаемым до сообщения, из которого он взялся.

Посессионный watermark гарантирует, что `PreCompact` и `SessionEnd` не запишут одну реплику дважды, и он сдвигается только после **подтверждённой** записи — недоступный на минуту brain будет повторён на следующем хуке, а не пропущен.

### Поведение при сбое

Оба хука молчат и не мешают. Нет ключа, нет `node` в `PATH`, brain лежит, пришёл кривой payload — exit 0 и ни строчки в вывод. Слой памяти, способный сломать рабочую сессию, хуже отсутствия слоя памяти, поэтому у этого правила нет исключений.

## Свой вариант

Скрипты — около 200 строк, и их стоит прочитать перед адаптацией: [`hooks/brain-hook.mjs`](https://github.com/inite-ai/inite-brain-service/blob/main/plugins/inite-brain/hooks/brain-hook.mjs). Форма одинакова в любом харнесе, который умеет запускать команду на событие (lifecycle-хуки Codex CLI, расширения Gemini CLI, git-хук, скрипт-обёртка):

**Recall** — один POST, отрисовать, напечатать:

```bash
curl -s -X POST "$BRAIN_URL/v1/search" \
  -H "Authorization: Bearer $BRAIN_KEY" \
  -H "Content-Type: application/json" \
  -d "{\"query\": \"$PROJECT\", \"limit\": 8}"
```

Дальше — что харнес принимает как подкладываемый контекст. Claude Code ждёт JSON в stdout:

```json
{
  "hookSpecificOutput": {
    "hookEventName": "SessionStart",
    "additionalContext": "Что brain помнит о …"
  }
}
```

**Capture** — один POST, извлечение на стороне сервера:

```bash
curl -s -X POST "$BRAIN_URL/v1/ingest/mention" \
  -H "Authorization: Bearer $BRAIN_KEY" \
  -H "Content-Type: application/json" \
  -d "{
    \"text\": \"$SESSION_TEXT\",
    \"contextRef\": { \"vertical\": \"chat\", \"recorder\": \"my-harness\" },
    \"emittedAt\": \"$(date -u +%Y-%m-%dT%H:%M:%SZ)\"
  }"
```

Три правила, которые стоит скопировать:

1. **Ограничь payload.** `text` на сервере обрезается на 16 000 символах; режь с начала, чтобы выжили свежие реплики.
2. **Держи watermark.** Любой харнес, у которого есть и «перед компактификацией», и «в конце», иначе запишет одни и те же реплики дважды.
3. **Никогда не падай громко.** Глотай все ошибки. Пользователь не спрашивал у слоя памяти мнения о его собственной доступности.

## Скоуп на пользователя

Если один ключ воркспейса на нескольких людей — ставь стабильный `userId` и в поиск, и в ingest. Тогда чтение возвращает общую память тенанта плюс личные строки этого человека, а запись фенсится на него. Не ставить его с обеих сторон — это режим общей памяти тенанта, и это fail-closed по умолчанию, а не случайность.
