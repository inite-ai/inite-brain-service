# Справочник MCP-инструментов

Сервер регистрирует **до 30 встроенных инструментов + 2 ресурса** на `McpServer({ name: 'inite-brain-service' })`, с гейтингом по scope: 19 на чтение (`brain:read`) всегда, плюс ещё 2 инструмента чтения (`get_fact`, `get_fact_provenance`) при `FACTS_API_ENABLED=1` на сервере; ещё 8 с `brain:write` (один из них, `ingest_document`, регистрируется только при `DOCUMENT_INGEST_ENABLED=1`) и 1 с `brain:admin`. Чувствительным PII-значениям нужен дополнительный scope `brain:read_pii`. Поверх встроенных установленные Domain Packs могут добавлять одобренные оператором namespaced-инструменты — см. раздел «Инструменты из паков» ниже. На этой странице описаны самые используемые инструменты; полный список (communities, процедурная память, репутация источников, code memory) перечислен по scope в [матрице scope настройки MCP](/ru/docs/mcp/setup) и в [`docs/api.md`](https://github.com/inite-ai/inite-brain-service/blob/main/docs/api.md) репозитория.

## search_knowledge

> Семантический поиск по графу знаний компании. Возвращает сущности с топ-фактами и external-ссылками назад в исходные вертикали. Применяй `asOf` для исторических запросов «что мы знали на X».

**Нужный scope:** `brain:read`

```ts
{
  query: string                  // required — natural language
  limit?: number                 // 1..100, default 10
  predicates?: string[]          // restrict to these predicates
  asOf?: string                  // ISO 8601 — bitemporal cutoff
  minConfidence?: number         // 0..1 — drop low-confidence facts
  userId?: string                // per-user memory scope (tenant-global + this user)
}
```

В паре со скиллом `brain-search` в `~/.claude/skills/brain-search/`.

## get_entity_profile

> Полный профиль одной сущности: каноническое имя, тип, externalRefs и активные факты. Через `externalRefs` подтягивай свежее состояние из исходной вертикали (например, клиентом `@inite/knowledge`).

**Нужный scope:** `brain:read`

```ts
{
  entityId: string               // brain id or `vertical.id` shorthand
  asOf?: string
}
```

## get_entity_timeline

> Хронологический аудит всех фактов, что Brain узнал о сущности, включая отозванные. Полезно для разбирательств «что мы знали и когда».

**Нужный scope:** `brain:read`

```ts
{
  entityId: string
  since?: string
  until?: string
}
```

Возвращает и отозванные строки — инвариант аудита.

## find_related_entities

> Сущности, связанные с данной через граф знаний. Только один шаг — для multi-hop зови рекурсивно.

**Нужный scope:** `brain:read`

```ts
{
  entityId: string
  kind?: string                  // edge filter, e.g. 'paid_for', 'mentioned_in', 'identity_of'
}
```

## get_fact

> Прочитать один факт как он хранится — предикат (aspect), объект (statement), confidence, окно валидности, атрибуция источника и состояние жизненного цикла. Отозванные факты по-прежнему резолвятся (`retracted: true`); в not-found превращаются только фенсы видимости. `groundingStatus` (`grounded` | `ungrounded`) появляется на фактах, проштампованных плоскостью claim-grounding (`EVIDENCE_GROUNDING_STAMP`); на легаси-строках ключа нет.

**Нужный scope:** `brain:read` — регистрируется только при `FACTS_API_ENABLED=1` на сервере (REST-близнец `GET /v1/facts/:id`).

```ts
{
  factId: string                 // knowledge_fact:… or short id
}
```

## get_fact_provenance

> Показать, почему факт запомнен: дословные реплики разговора, из которых он выведен (хронологически, с char-span цитатами, если деривер их проштамповал). Серверы с флагами рекурсивного замыкания дополнительно возвращают `derivedFacts` + `closure` (транзитивный граф поддержки) и типизированные `supportEdges` — это passthrough `GET /v1/facts/:id/provenance`, без фильтрации полей.

**Нужный scope:** `brain:read` — тот же гейт `FACTS_API_ENABLED`, что и у `get_fact`.

```ts
{
  factId: string
}
```

## record_fact

> Вставить факт о сущности. Запускает разрешение конфликтов brain (`INSERTED` / `SUPERSEDED` / `COMPETING` / `REJECTED`). Из агентов используй экономно — большинство фактов должно приходить через ингест событий.

**Нужный scope:** `brain:write`

```ts
{
  entityRef:
    | { vertical: string, id: string }
    | { entityId: string }
  predicate: string
  object: string
  validFrom: string              // ISO 8601 — required
  validUntil?: string
  confidence?: number            // 0..1
  sourceVertical: string         // attributed source vertical
  userId?: string                // per-user memory scope
  conversationId?: string        // grounding: the conversation this was observed in
  evidence?: Array<{             // grounding: ≤10 typed observation pointers
    kind: 'event' | 'message' | 'conversation' | 'url' | 'document' | 'commit' | 'other'
    ref: string                  // the pointer itself — id, URL, path, sha…
    note?: string
  }>
}
```

Передавай `conversationId` и/или `evidence[]` всегда, когда можешь — именование наблюдения за утверждением помечает факт **grounded** на плоскости claim-grounding (серверы, штампующие `groundingStatus`, считают «голые» записи навсегда безнаблюдательными — такие факты могут исключаться из консолидации и строгого сервинга). Проверяй результат через `get_fact`.

## retract_fact

> Пометить факт как больше не подтверждаемый. Каскадит на производные факты. Не удаляет; строка остаётся для аудита.

**Нужный scope:** `brain:write`

```ts
{
  factId: string
  reason: string                 // required
}
```

## Инструменты из паков

[Domain Pack](/ru/docs/platform/domain-packs) может нести секцию `mcpTools` — до 8 инструментов, добавляемых на MCP-поверхность тенанта под именем `<packId>__<toolName>` (двойное подчёркивание — зарезервированный разделитель). Инструмент пака бывает ровно двух видов — сторонний код внутри Brain не выполняется никогда:

- **`query`** — декларативное чтение по СОБСТВЕННЫМ namespaced-предикатам пака (поверхности `search` или `facts_by_predicate`). Схемы входа фиксируются на стороне сервера; пак выбирает имена и описания, но не форму запроса.
- **`external`** — HTTPS-прокси с HMAC-подписью на эндпоинт издателя пака. По проводу уходит непрозрачный per-install `installId`, но никогда — id тенанта; ответы ограничены по размеру (64 КБ) и таймауту, а circuit breaker на эндпоинт защёлкивается после серии сбоев.

Согласие — явное: установка пака с секцией `mcpTools` падает с `400`, если в запросе нет `acceptMcpTools: true`; апгрейд, меняющий секцию, требует согласия заново.

Всё закрыто флагами оператора:

| Флаг | По умолчанию | Значение |
| --- | --- | --- |
| `MCP_PACK_TOOLS_ENABLED` | `0` | Главный выключатель — при выключенном MCP-поверхность состоит ровно из встроенных семейств |
| `MCP_PACK_QUERY_TOOLS_ENABLED` | `1` | Query-инструменты (достижимы только под главным флагом) |
| `MCP_PACK_EXTERNAL_TOOLS_ENABLED` | `0` | Внешние прокси-инструменты |

Полный справочник — поля манифеста, флоу согласия, протокол эндпоинта с проверкой подписи, модель безопасности: [`docs/mcp-pack-tools.md`](https://github.com/inite-ai/inite-brain-service/blob/main/docs/mcp-pack-tools.md) в репозитории.

## Общая форма ответа

Каждый инструмент возвращает:

```ts
{
  content: [{ type: 'text', text: <JSON string> }],
  structuredContent: <typed object>
}
```

Парсить клиентам стоит `structuredContent`. Зеркало в `text` — для клиентов, которые ещё не уважают `structuredContent`.

## Ошибки

Вызовы инструментов возвращают MCP error-фреймы с такими паттернами:

| Паттерн | Причина |
| --- | --- |
| `"scope brain:write required"` | Инструменту нужен scope, которого нет у ключа |
| `"MCP path companyId (...) does not match ApiKey companyId"` | companyId в URL ≠ companyId ключа |
| `"unknown predicate '<x>'"` | Словарь отверг предикат — зарегистрируй или возьми стандартный |
| `"validFrom must be ISO 8601"` | Несовпадение формата в `record_fact` |
