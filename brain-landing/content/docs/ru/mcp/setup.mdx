# Настройка MCP

Brain отдаёт Streamable HTTP MCP-эндпоинт в двух написаниях:

- `https://brain.inite.ai/mcp` — тенант берётся из креда. Это форма для клиента, который знает только URL, — то есть для любого коннектора, найденного через OAuth.
- `https://brain.inite.ai/mcp/<companyId>` — явная; путь обязан совпасть с тенантом креда, иначе 400.

Поверхность одна и та же. Неаутентифицированная проба отвечает на `/mcp/health` и `/mcp/<companyId>/health` — проверить доступность можно без ключа.

## Что нужно

1. **API-ключ** brain (формат `brain_<hex>`). Выпусти его на [экране ключей](/ru/app/keys) — ключ показывается один раз и хранится только хэшем — или через API: `POST /v1/keys` любым уже имеющимся кредом. Селф-хост? Первый ключ берётся из `BRAIN_API_KEYS`, все следующие выпускаются тем же эндпоинтом ([getting started](/ru/docs/getting-started)).
2. **companyId**, на который выдан ключ — виден на экране ключей и в ответе на выпуск.
3. **MCP-URL**: `https://brain.inite.ai/mcp/<companyId>` — тоже возвращается как `mcpUrl` при выпуске.

Brain не принимает анонимный MCP-трафик. Режима общего секрета нет.

## Claude Desktop

Правь `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) или `%APPDATA%\Claude\claude_desktop_config.json` (Windows):

```json
{
  "mcpServers": {
    "brain": {
      "command": "npx",
      "args": [
        "-y",
        "@inite/brain-mcp"
      ],
      "env": {
        "BRAIN_API_KEY": "brain_YOUR_API_KEY",
        "BRAIN_COMPANY_ID": "YOUR_COMPANY_ID"
      }
    }
  }
}
```

Полностью выйдите из Claude Desktop и откройте его заново. Официальный коннектор передаёт инструменты и ресурсы сервера. Их доступность зависит от прав ключа, настроек сервера и установленных пакетов. Для коннектора нужны Node.js и npx.

## Cursor

`.cursor/mcp.json` в воркспейсе (или `~/.cursor/mcp.json` глобально):

```json
{
  "mcpServers": {
    "brain": {
      "url": "https://brain.inite.ai/mcp/<companyId>",
      "transport": "http",
      "headers": {
        "Authorization": "Bearer <api-key>"
      }
    }
  }
}
```

Перезагрузи воркспейс. Инструменты brain станут доступны как `@brain.<tool>` в панели чата.

## Goose

`~/.config/goose/config.yaml`:

```yaml
extensions:
  brain:
    type: streamable_http
    uri: https://brain.inite.ai/mcp/<companyId>
    headers:
      Authorization: Bearer <api-key>
    enabled: true
```

`goose session start` подгрузит инструменты brain.

## n8n

В ноде **MCP Client**:

- URL: `https://brain.inite.ai/mcp/<companyId>`
- Transport: HTTP (Streamable)
- Header: `Authorization: Bearer <api-key>`

Закрепи credential, чтобы переиспользовать между воркфлоу.

## Hermes (Nous Research)

[Hermes Agent](https://hermes-agent.nousresearch.com) поддерживает remote MCP нативно. Добавь brain в `mcp_servers` файла `~/.hermes/config.yaml`:

```yaml
mcp_servers:
  brain:
    url: "https://brain.inite.ai/mcp/<companyId>"
    headers:
      Authorization: "Bearer <api-key>"
    tools:
      exclude: [forget_entity]   # опционально — спрятать деструктивный admin-инструмент
```

Hermes на старте обнаружит инструменты brain и зарегистрирует их в своём общем реестре. Фильтры `tools.include` / `tools.exclude` позволяют отдать агенту только нужную поверхность.

## Харнесы только с stdio — коннектор `@inite/brain-mcp`

Некоторые харнесы умеют запускать MCP-серверы только как **stdio**-подпроцессы и не могут прикрепить заголовок `Authorization` — MCP-клиент [openclaw](https://github.com/openclaw/openclaw) только stdio, как и Goose 1.x. Для них есть first-party коннектор stdio↔HTTP [`@inite/brain-mcp`](https://www.npmjs.com/package/@inite/brain-mcp). Харнес спавнит его по stdio, а он прозрачно проксирует каждый доступный по scope инструмент на удалённый эндпоинт, пробрасывая Bearer-ключ из `env`:

```
харнес ──stdio──▶ @inite/brain-mcp ──HTTP + Bearer──▶ /mcp/<companyId>
```

Это чистый проксипасс — с v0.2 вербатим форвардятся `tools/list` / `tools/call` И поверхность ресурсов (`resources/list`, `resources/templates/list`, `resources/read` — ресурсы `brain://entity/…`), так что агент видит ровно ту поверхность, что открывает ключ. Sampling мостится в обратную сторону: запросы brain `sampling/createMessage` (от `summarize_entity` со `styleHint='client_llm'`) форвардятся харнесу, чтобы сводку писала его собственная модель; харнес без capability sampling получает чистую ошибку, и brain откатывается на локальный шаблон. Пропиши его в MCP-конфиг харнеса (пример для `mcp.servers` у openclaw):

```json
{
  "mcp": {
    "servers": {
      "brain": {
        "command": "npx",
        "args": ["-y", "@inite/brain-mcp"],
        "env": {
          "BRAIN_API_KEY": "brain_xxxxxxxx",
          "BRAIN_COMPANY_ID": "<companyId>"
        }
      }
    }
  }
}
```

| Переменная | Обязательна | По умолчанию | Примечание |
| --- | --- | --- | --- |
| `BRAIN_API_KEY` | да | — | твой ключ `brain_…` |
| `BRAIN_COMPANY_ID` | да\* | — | \*не нужна, если задан `BRAIN_MCP_URL` |
| `BRAIN_BASE_URL` | нет | `https://brain.inite.ai` | для self-hosted brain |
| `BRAIN_MCP_URL` | нет | — | полный override эндпоинта; важнее base + company |

Аутентификация, изоляция тенантов, scopes и PII-фенс по-прежнему энфорсятся на стороне brain из ключа — коннектор лишь несёт токен. Харнесам, которые уже умеют remote MCP (Hermes, Claude Desktop, Cursor, Goose v2), коннектор не нужен — им прямой URL-конфиг выше; коннектор только для случая stdio-only.

## Smoke-тест

Когда подключился, попроси ассистента:

> Покажи доступные инструменты brain и вызови `search_knowledge` с query `"hello"` limit 1.

Ты увидишь количество инструментов, соответствующее scope ключа (20 для read-only — 22 при `FACTS_API_ENABLED` — до 32 для read+write+admin), и результат `search_knowledge` — либо пустой (свежий тенант), либо одно попадание (seed-данные).

Получил 401 — bearer-токен битый или ключ невалиден. Получил `400: MCP path companyId (...) does not match ApiKey companyId` — вставил не тот companyId для этого ключа.

## Матрица scope

| Scope | Видимые инструменты |
| --- | --- |
| `brain:read` (всегда) | **20 инструментов чтения** — поиск (`search_knowledge`, `search_multi_hop`, `synthesize`, `memory_diff`, `graph_retrieve`), чтение сущностей (`get_entity_profile`, `get_entity_timeline`, `summarize_entity`, `get_competing_facts`, `find_related_entities`, `detect_contradiction`), сообщества (`search_communities`, `list_communities`, `find_entity_communities`), процедурная память (`match_procedure`, `list_procedures`), репутация источников (`get_source_reputation`), code memory (`why`, `recall_decisions`), онбординг (`workspace_status`) — **22** при `FACTS_API_ENABLED=1` на сервере (добавляются `get_fact`, `get_fact_provenance`) — плюс 2 ресурса (`brain://entity/{id}`, `brain://entity/{id}/timeline`) |
| `brain:write` (дополнительно) | **+9 инструментов записи** — `record_fact`, `link_entities`, `retract_fact`, `record_procedure`, `retire_procedure`, `record_feedback`, `record_decision`, `ingest_document` (регистрируется только при `DOCUMENT_INGEST_ENABLED=1` у оператора) и `rename_workspace` — он регистрируется, только пока у воркспейса нет имени, и исчезает, как только имя появилось |
| `brain:admin` (дополнительно) | **+1** — `forget_entity`, деструктивный GDPR-каскад |
| `brain:read_pii` (дополнительно) | новых инструментов нет — открывает значения `email` / `phone` / `dob` / `address` в результатах |
| `brain:read_media` (дополнительно) | новых инструментов нет — доступ к медиа/биометрическим уликам, более строгий режим, чем `brain:read_pii`; только для оператора хостинга (env-key конфиг, через токены не выдаётся) |

Установленные [Domain Packs](/ru/docs/platform/domain-packs) с одобренной секцией `mcpTools` добавляют поверх этого свои инструменты (`<packId>__<tool>`) — см. [справочник инструментов](/ru/docs/mcp/tools).

Ключ только с `brain:read` видит 20 инструментов (22 при `FACTS_API_ENABLED`), а не 32. Это инвариант безопасности, а не баг.

## Профили инструментов — не платить за то, что не зовёшь

Каждый инструмент в `tools/list` стоит контекста всю сессию — звали его или нет, — а сервер stateless, поэтому определения пересылаются каждый ход. Замер тем же токенизатором, по которому считают модели: полная поверхность — **7 078 токенов**, `core` — **2 052**.

Добавь `?tools=core` к MCP-URL:

```text
https://brain.inite.ai/mcp?tools=core
```

| Профиль | Показывает | Для кого |
| --- | --- | --- |
| `full` (по умолчанию) | всё, что открывает ключ — 20 на чтение, до 32 с write + admin | Агенты, которые пользуются всей поверхностью; ровно как было до профилей |
| `core` | `search_knowledge`, `synthesize`, `memory_diff`, `get_entity_timeline`, `record_fact`, `workspace_status` плюс `find_tool` и `run_tool` | Долгоживущие кодовые агенты, всё, где контекст — дефицит |

**`core` — это сужение, а не потеря.** Остальные инструменты остаются доступны:

- `find_tool({ query: "кто с этим не согласен" })` ищет непоказанные инструменты по намерению и возвращает их настоящие JSON-Schema аргументы.
- `run_tool({ name, args })` выполняет любой из них.

Права в обоих случаях одинаковые. `run_tool` вызывает тот же хендлер, до которого доходит прямой вызов — проверки скоупов, ABAC-политика, RFC 9396 гранты и PII-фенсинг работают — а инструмент, который убрал гейт, отвечает ровно как никогда не существовавший.

Оператор задаёт дефолт через `MCP_TOOL_PROFILE_DEFAULT=core`; параметр в URL его перебивает. Нераспознанное значение — `400`, а не тихий откат к полной поверхности: получить 32 инструмента вместо 8 не должно выясняться по счёту за токены.

Health-проба тоже отвечает по профилю: `GET /mcp/health?tools=core` вернёт `profile` и те инструменты, которые этот URL отдаст.

## Stateless-режим

Brain держит MCP без состояния: один McpServer на запрос, без session id. MCP-клиентам, которым нужны долгие сессии, стоит звать по разу на использование инструмента — на стороне brain нет стоимости установки. Сессии с состоянием можно добавить через `sessionIdGenerator`, если появится кейс.
