# POST /v1/search

Hybrid retrieval over a per-tenant knowledge graph. Vector + BM25 + optional HyPE legs → convex fusion → predicate-router boost → optional cross-encoder → listwise LLM rerank with self-consistency → entity-fact backfill.

## Request

```http
POST /v1/search
Authorization: Bearer <api-key>
Content-Type: application/json
```

```ts
{
  query: string                    // natural language, ≤ 8 000 chars
  limit?: number                   // 1..100, default 10
  predicates?: string[]            // optional filter — restrict to these predicates
  entityTypes?: string[]           // restrict to these entity types
  entityIds?: string[]             // anchor on known entities (multi-hop chaining)
  asOf?: string                    // ISO 8601 — historical cutoff
  minConfidence?: number           // 0..1 — drop facts below this raw confidence
  includeContested?: boolean       // include COMPETING facts
  includeStale?: boolean           // ignore validity windows (audit shape)
  includeRetracted?: boolean       // include retracted rows too
  searchMode?: 'vector' | 'lexical' | 'hybrid'  // retrieval strategy, default hybrid
  userId?: string                  // per-user memory scope (tenant-global + this user)

  // Agent primitives (KnowQL-style)
  confidenceFloor?: number         // 0..1 — floor AFTER decay × source-trust weighting
  requireProvenance?: boolean      // drop facts without a source trail
  tokenBudget?: number             // 50..50000 — cap response size, tiktoken-exact
  outputShape?: 'full' | 'compact' | 'ids'  // response verbosity
}
```

Field notes:

- **`searchMode`** — `hybrid` (default) fuses vector + BM25 via reciprocal-rank
  fusion; `vector` is embedding-only (paraphrastic / cross-lingual queries);
  `lexical` is BM25-only (exact-token matching: ids, regulatory text).
- **`userId`** — per-user memory scope: results include tenant-global facts plus
  this user's personal ones; omit for tenant-global only (fail-closed).
- **`confidenceFloor`** — stricter than `minConfidence`: applies after decay and
  source-trust weighting. Agentic callers that can't tolerate noise set ≥ 0.5.
- **`requireProvenance`** — every returned fact must carry a non-empty `source`
  object; compliance flows that cite-and-link back use this.
- **`tokenBudget`** — the server drops lowest-scoring entities until the
  serialized response fits; counted with tiktoken's `cl100k_base`, the same
  encoding your LLM bill uses.
- **`outputShape`** — `full` (entities + facts + scores), `compact` (top fact
  per entity, no scores), `ids` (entity ids only — cheapest).
- **`entityIds`** — restrict to facts owned by these entities; hop N of a
  multi-hop chain anchors on ids emitted by hop N-1.

## Response

```ts
{
  hits: Array<{
    entity: {
      id: string
      name: string
      type: string
      externalRefs: Array<{ vertical: string, id: string }>
    }
    facts: Array<{
      factId: string
      predicate: string
      object: string | null  // null when PII-gated
      validFrom: string
      validUntil: string | null
      confidence: number
      status: 'active' | 'superseded' | 'retracted'
      sourceVertical?: string
    }>
    score: number          // post-rerank fused score
    legScores: {           // per-leg contribution; useful for debugging
      vector?: number
      lexical?: number
      hype?: number
    }
  }>
  diagnostics?: {
    router?: { predicates: Record<string, number>, types: Record<string, number> }
    rerank?: { invoked: boolean, n: number, skippedReason?: string }
    cacheHit?: boolean
  }
}
```

## Pipeline stages

The pipeline runs in one HTTP call. Each stage is feature-flagged at the service level — operators flip them per tenant.

**Graph-first, with vector as the door.** The unit of retrieval is a typed fact on the knowledge graph — never a text chunk. The vector and BM25 legs exist for one job: mapping a free-text query onto candidate facts (you need *some* way into the graph from natural language). Everything downstream is graph-native — the router works over the predicate ontology, candidates bucket per entity, edge expansion and PPR are literal graph walks, and the bitemporal closure plus trust/corroboration multipliers are graph semantics. Queries that already name their anchors skip the doors entirely: `graph_retrieve` (entities → 1-hop neighbourhood) and the multi-hop planner enter the graph directly, and profile/timeline reads never touch a vector at all.

```
                   query
                     │
                     ▼
       ┌─────────────────────────────┐
       │ predicate + type router     │  joint LLM call → soft distribution
       │ (LRU-cached per query hash) │
       └─────────────────────────────┘
                     │
       ┌─────────────┼─────────────┐
       ▼             ▼             ▼
  vector leg   lexical leg   (HyPE alt-emb leg)
  (HNSW cos)   (BM25)        max(cos_main, cos_alt)
       │             │             │
       └─────────────┼─────────────┘
                     ▼
       convex-fusion (CombMNZ-flavoured w=0.5)
                     │
                     ▼
       decay × confidence × predicate-boost-α
                     │
                     ▼
       group-by-entity ──→  PPR prior (HippoRAG, opt-in)
                     │
                     ▼
       cross-encoder (Cohere Rerank v3.5, opt-in)
                     │
                     ▼
       listwise LLM reranker (RankGPT-style + self-consistency)
                     │
                     ▼
       entity-fact backfill (native Surreal inline subquery)
                     │
                     ▼
                  results
```

## Bitemporal cutoff

`asOf` pushes into the WHERE clause at the leg level:

```sql
WHERE validFrom <= $asOf
  AND (validUntil IS NULL OR validUntil > $asOf)
  AND (retractedAt IS NULL OR retractedAt > $asOf)
```

No JS post-filter, no double round-trip.

## PII gating

If the caller's API key lacks `brain:read_pii`, sensitive predicates (`email`, `phone`, `dob`, `address`) return with `object: null`. The predicate is still visible — that's the “we have this data, you don't have rights” signal. Tighter than 403 because you can still rank entities by the *presence* of identifying facts.

## Per-leg CI

Every release runs `pnpm test:eval` which bootstraps a 95% CI over each leg's recall@1, MRR, NDCG@10. Numbers are written to `.eval-baseline/main.json`. Drop more than 3pp = CI block.
