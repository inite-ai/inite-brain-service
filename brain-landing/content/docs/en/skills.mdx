# Skills bundle

Brain ships six Anthropic Skills that teach an AI agent how to use the MCP surface. They're plain markdown — `SKILL.md` with YAML frontmatter — and Claude reads them natively when they land in `~/.claude/skills/`.

## One-line install

```sh
curl -fsSL https://brain.inite.ai/install.sh | sh
```

By default it installs into **every agent it finds on the machine**. `SKILL.md` became a cross-agent format in 2026, so the same six skills work unchanged in each of them — only the destination directory ever differed.

| Target | User-global | Project |
| --- | --- | --- |
| `claude` | `~/.claude/skills/` | `.claude/skills/` |
| `codex` | `$CODEX_HOME/skills/` (default `~/.codex`) | `.codex/skills/` |
| `gemini` | `~/.gemini/skills/` | `.gemini/skills/` |
| `openclaw` | `$OPENCLAW_STATE_DIR/skills/` (default `~/.openclaw`) | `.openclaw/skills/` |
| `opencode` | `~/.config/opencode/skills/` | `.opencode/skills/` |
| `cursor` | — (project only) | `.cursor/skills/` |
| `agents` | — (project only) | `.agents/skills/` — the vendor-neutral path |

Flags:

- `--target auto` (default) — every agent already installed here. Project-only targets are skipped unless you ask for them, so a piped one-liner never writes into whatever directory you happened to be in.
- `--target all` — every target in the table
- `--target codex,gemini` — a comma-separated subset
- `--scope project` — install into `$PWD` instead of the home directory
- `--list` / `--dry-run` — resolve destinations, write nothing
- `--target project` and `--target user` still mean Claude Code, as they always did

The installer downloads `skills.tar.gz`, unpacks each skill into `<target>/<name>/SKILL.md`, and drops a `VERSION.brain` file alongside so the staleness check has a single number to compare against.

Claude Code users can install the skills, the MCP server and the [lifecycle hooks](/en/docs/mcp/hooks) together instead:

```
/plugin marketplace add inite-ai/inite-brain-service
/plugin install inite-brain@inite
```

## The six skills

| Skill | Activates when… | What it teaches |
| --- | --- | --- |
| `brain-search` | The user asks to find / look up / search knowledge | How to call `search_knowledge` (+ `search_multi_hop` / `synthesize`) with predicate hints and asOf semantics |
| `brain-recall` | The user names an entity and asks for the full picture | How to combine `summarize_entity` + `get_entity_profile` + `get_entity_timeline` + `find_related_entities` + `get_competing_facts` |
| `brain-bitemporal` | The user has a temporal question (“on X date”, “before Y”) | asOf semantics, `memory_diff`, validFrom / validUntil, retracted-row handling |
| `brain-write` | The user wants to record / merge / revise structured knowledge | `record_fact` / `link_entities` / `retract_fact` with a `detect_contradiction` preflight |
| `brain-conflict` | Two facts disagree on the same predicate (COMPETING status) | Adjudication workflow via `get_competing_facts` + `detect_contradiction` |
| `brain-mcp-setup` | The user is wiring brain MCP into a new client | Step-by-step config for Claude Desktop, Cursor, Goose v2, Aider, Continue.dev, n8n, and a raw `@modelcontextprotocol/sdk` client |

## Format

Each `SKILL.md` is:

```yaml
---
name: brain-search
description: One-line summary the agent reads before deciding to activate this skill.
---

# Heading and instructions follow — pure markdown.
```

No JS runtime, no MCP wiring inside the skill itself. The wire-up lives in brain-service; the skill is the agent's how-to-use brief.

## Versioning model

Single semver in `skills/VERSION`. No per-skill semvers. The whole bundle ships as one versioned unit.

```bash
cat ~/.claude/skills/VERSION.brain
# → 0.3.0
```

Bumped automatically by `pnpm skills:bump --staged` on pre-commit when any file under `skills/<name>/**` changes. Patch-bump only — manual minor / major: edit `skills/VERSION`, then `pnpm skills:build`.

## Updating

```sh
# Re-run the installer at any time — it overwrites in place.
curl -fsSL https://brain.inite.ai/install.sh | sh
```

The installer is idempotent. It replaces the contents of `~/.claude/skills/brain-*` and refreshes `VERSION.brain`.

## Layout

```
~/.claude/skills/
├── VERSION.brain             ← bundle version, single source of truth
├── CHANGELOG.brain.md
├── brain-search/SKILL.md
├── brain-recall/SKILL.md
├── brain-bitemporal/SKILL.md
├── brain-write/SKILL.md
├── brain-conflict/SKILL.md
└── brain-mcp-setup/SKILL.md
```

## Authoring a custom skill

The bundle is open — add your own `brain-*` skill if you need a workflow brain doesn't ship. Layout:

```
skills/brain-mycustom/SKILL.md
```

Frontmatter must have `name` (= folder name) and `description`. Body is plain markdown. After editing:

```sh
pnpm skills:bump --note "feat(brain-mycustom): teach the agent <thing>"
pnpm skills:pack
```

This patch-bumps `VERSION`, appends a CHANGELOG entry, and produces `brain-landing/public/skills.tar.gz` for the next deploy.
