# MCP setup

Brain ships a Streamable HTTP MCP endpoint in two spellings:

- `https://brain.inite.ai/mcp` — the tenant comes from the credential. Use this when the client only knows a URL, which is every OAuth-discovered connector.
- `https://brain.inite.ai/mcp/<companyId>` — explicit; the path must match the credential's tenant, or the call is a 400.

Both serve the same surface. An unauthenticated probe answers at `/mcp/health` and `/mcp/<companyId>/health` — reachability without a key.

## What you need

1. A brain **API key** (format `brain_<hex>`). Issue one on the [keys screen](/en/app/keys) — it is shown once and stored only as a hash — or over the API with `POST /v1/keys` using a credential you already hold. Self-hosting? The first key comes from `BRAIN_API_KEYS`; every key after it can be issued through the same endpoint ([getting started](/en/docs/getting-started)).
2. The **companyId** the key was issued for — the keys screen shows it, and so does every issuing response.
3. The **MCP URL**: `https://brain.inite.ai/mcp/<companyId>` — also returned as `mcpUrl` when a key is issued.

Brain refuses anonymous MCP traffic. There is no shared-secret mode.

## Claude Code

One command installs the whole integration — MCP server, the six [skills](/en/docs/skills), and the [lifecycle hooks](/en/docs/mcp/hooks) that make memory happen without the model having to remember to write:

```
/plugin marketplace add inite-ai/inite-brain-service
/plugin install inite-brain@inite
```

Claude Code prompts for the API key at enable time and stores it in the OS keychain rather than in a config file. Nothing else to paste: the tenant comes from the key.

To wire only the MCP server, by hand:

```bash
claude mcp add --transport http brain https://brain.inite.ai/mcp \
  --header "Authorization: Bearer $BRAIN_KEY"
```

Or commit it to the repo as `.mcp.json`, so everyone working in it gets the same memory:

```json
{
  "mcpServers": {
    "brain": {
      "type": "http",
      "url": "https://brain.inite.ai/mcp",
      "headers": {
        "Authorization": "Bearer ${BRAIN_KEY}"
      }
    }
  }
}
```

`${BRAIN_KEY}` expands from the environment, so the committed file carries no secret.

## Codex CLI

`~/.codex/config.toml` (or `.codex/config.toml` in the project, which wins):

```toml
[mcp_servers.brain]
url = "https://brain.inite.ai/mcp"
bearer_token_env_var = "BRAIN_KEY"
```

Codex reads `BRAIN_KEY` from the environment at connect time and sends it as `Authorization: Bearer` — the token never lands in the config file.

## ChatGPT connectors

ChatGPT's deep-research and company-knowledge connectors accept exactly two read-only tools, named `search` and `fetch`, with prescribed result shapes — a connector that exposes anything else is refused. Brain serves that shape on its own URL:

```text
https://brain.inite.ai/mcp?tools=chatgpt
```

Add it as a custom connector. ChatGPT runs OAuth itself: the 401 advertises the [protected-resource metadata](https://brain.inite.ai/.well-known/oauth-protected-resource), the client registers itself, and the workspace arrives in the token — nothing to paste beyond the URL.

| Tool | Returns |
| --- | --- |
| `search(query)` | `{ results: [{ id, title, text, url }] }` — one entry per memory record, with a short summary of what is known |
| `fetch(id)` | `{ id, title, text, url, metadata }` — every fact held about that record, each with the window it is true for |

`url` points at the entity screen in the web app, which is what turns a result into a **citation**: ChatGPT builds citation metadata only when the link is a non-empty string, and this one opens the record it cites. On a self-hosted deployment with no `BRAIN_PUBLIC_URL`, the field is empty and results stay ordinary tool output.

The facade is read-only by construction — there is no write tool in it — and it is a projection of the same memory, not a copy: what `fetch` returns includes the validity window on every fact, which is the part a document store cannot tell you.

## Claude Desktop

Edit `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) or `%APPDATA%\Claude\claude_desktop_config.json` (Windows):

```json
{
  "mcpServers": {
    "brain": {
      "command": "npx",
      "args": [
        "-y",
        "@inite/brain-mcp"
      ],
      "env": {
        "BRAIN_API_KEY": "brain_YOUR_API_KEY",
        "BRAIN_COMPANY_ID": "YOUR_COMPANY_ID"
      }
    }
  }
}
```

Quit Claude Desktop fully and reopen. The first-party connector forwards tools and resources from the server. Available tools depend on the key scopes, server features and installed packs. The connector requires Node.js and npx.

## Hermes (Nous Research)

The [Hermes Agent](https://hermes-agent.nousresearch.com) supports remote MCP natively. Add brain under `mcp_servers` in `~/.hermes/config.yaml`:

```yaml
mcp_servers:
  brain:
    url: "https://brain.inite.ai/mcp/<companyId>"
    headers:
      Authorization: "Bearer <api-key>"
    tools:
      exclude: [forget_entity]   # optional — hide the destructive admin tool
```

Hermes discovers brain's tools at startup and registers them into its normal tool registry. The `tools.include` / `tools.exclude` filters let you expose only the surface you want the agent to see.

## stdio-only harnesses — the `@inite/brain-mcp` connector

Some harnesses can only launch **stdio** MCP servers as subprocesses and have no way to attach an `Authorization` header — [openclaw](https://github.com/openclaw/openclaw)'s MCP client is stdio-only, and so is Goose 1.x. For these, use the first-party stdio↔HTTP connector [`@inite/brain-mcp`](https://www.npmjs.com/package/@inite/brain-mcp). The harness spawns it over stdio; it transparently proxies every scoped tool to the remote endpoint, carrying the Bearer key from `env`:

```
harness ──stdio──▶ @inite/brain-mcp ──HTTP + Bearer──▶ /mcp/<companyId>
```

It is a pure passthrough — as of v0.2, `tools/list` / `tools/call` AND the resource surface (`resources/list`, `resources/templates/list`, `resources/read` — the `brain://entity/…` resources) are forwarded verbatim, so the agent sees exactly the surface the key unlocks. Sampling is bridged in reverse: brain's `sampling/createMessage` requests (from `summarize_entity` with `styleHint='client_llm'`) are forwarded to the harness so its own model writes the summary; a harness that doesn't advertise sampling gets a clean error and brain falls back to its local template. Wire it into the harness's MCP config (shown here for openclaw's `mcp.servers`):

```json
{
  "mcp": {
    "servers": {
      "brain": {
        "command": "npx",
        "args": ["-y", "@inite/brain-mcp"],
        "env": {
          "BRAIN_API_KEY": "brain_xxxxxxxx",
          "BRAIN_COMPANY_ID": "<companyId>"
        }
      }
    }
  }
}
```

| Env var | Required | Default | Notes |
| --- | --- | --- | --- |
| `BRAIN_API_KEY` | yes | — | your `brain_…` key |
| `BRAIN_COMPANY_ID` | yes\* | — | \*not needed if `BRAIN_MCP_URL` is set |
| `BRAIN_BASE_URL` | no | `https://brain.inite.ai` | point at a self-hosted brain |
| `BRAIN_MCP_URL` | no | — | full endpoint override; wins over base + company |

Auth, tenancy isolation, scopes and PII fencing stay enforced server-side from the key — the connector only carries the token. Harnesses that already speak remote MCP (Hermes, Claude Desktop, Cursor, Goose v2) should use the direct URL config above instead; the connector is only for the stdio-only case.

## Smoke test

Once connected, ask the assistant:

> List available brain tools and call `search_knowledge` with query `"hello"` limit 1.

You should see the tool count that matches the key's scopes (20 for read-only — 22 with `FACTS_API_ENABLED` — up to 32 for read+write+admin) and a `search_knowledge` result that is either empty (fresh tenant) or one hit (seed data).

If you get a 401, the bearer token is malformed or the key is invalid. If you get `400: MCP path companyId (...) does not match ApiKey companyId`, you've pasted the wrong companyId for this key.

## Scope matrix

| Scope | Tools visible |
| --- | --- |
| `brain:read` (always) | **20 read tools** — search (`search_knowledge`, `search_multi_hop`, `synthesize`, `memory_diff`, `graph_retrieve`), entity reads (`get_entity_profile`, `get_entity_timeline`, `summarize_entity`, `get_competing_facts`, `find_related_entities`, `detect_contradiction`), communities (`search_communities`, `list_communities`, `find_entity_communities`), procedural memory (`match_procedure`, `list_procedures`), source reputation (`get_source_reputation`), code memory (`why`, `recall_decisions`), onboarding (`workspace_status`) — **22** when the server runs with `FACTS_API_ENABLED=1` (adds `get_fact`, `get_fact_provenance`) — plus 2 resources (`brain://entity/{id}`, `brain://entity/{id}/timeline`) |
| `brain:write` (extra) | **+9 write tools** — `record_fact`, `link_entities`, `retract_fact`, `record_procedure`, `retire_procedure`, `record_feedback`, `record_decision`, `ingest_document` (registered only when the operator sets `DOCUMENT_INGEST_ENABLED=1`), and `rename_workspace` — which is registered only while the workspace is unnamed and disappears once it has a name |
| `brain:admin` (extra) | **+1** — `forget_entity`, the GDPR-grade destructive cascade |
| `brain:read_pii` (extra) | no new tools — unlocks `email` / `phone` / `dob` / `address` object values in results |
| `brain:read_media` (extra) | no new tools — media/biometric evidence access, a stricter regime than `brain:read_pii`; hosting-operator-only (env-key config, never mintable through tokens) |

Installed [Domain Packs](/en/docs/platform/domain-packs) with consented `mcpTools` add pack-declared tools (`<packId>__<tool>`) on top of these — see the [tools reference](/en/docs/mcp/tools).

A key with only `brain:read` sees 20 tools (22 with `FACTS_API_ENABLED`), not 32. That's the security invariant, not a bug.

## Tool profiles — paying less for tools you do not call

Every tool in `tools/list` costs context for the whole session, called or not — and this server is stateless, so the definitions are re-sent with every turn. Measured with the same tokeniser the models bill against, the full surface is **7 078 tokens**; `core` is **2 052**.

Add `?tools=core` to the MCP URL:

```text
https://brain.inite.ai/mcp?tools=core
```

| Profile | Lists | For |
| --- | --- | --- |
| `full` (default) | everything the key unlocks — 20 read-only, up to 32 with write + admin | Agents that use the whole surface; unchanged from before profiles existed |
| `chatgpt` | exactly `search` and `fetch` | ChatGPT connectors — see above |
| `core` | `search_knowledge`, `synthesize`, `memory_diff`, `get_entity_timeline`, `record_fact`, `workspace_status`, plus `find_tool` and `run_tool` | Long-running coding agents, anything where context is the scarce resource |

**`core` is a narrowing, not a loss.** The other tools stay reachable:

- `find_tool({ query: "who disagrees about this" })` searches the unlisted tools by intent and returns their real JSON-Schema arguments.
- `run_tool({ name, args })` executes any of them.

Permissions are identical either way. `run_tool` dispatches to the same handler a direct call reaches — scope checks, ABAC policy, RFC 9396 grants and PII fencing all apply — and a tool a gate removed answers exactly like a tool that never existed.

Operators set the deployment default with `MCP_TOOL_PROFILE_DEFAULT=core`, and a single workspace with `MCP_TOOL_PROFILE_OVERRIDES={"co_acme":"core"}` — read on every call, so a change needs no restart. Precedence is URL → workspace → deployment default. An unrecognised value is a `400`, never a silent fall back to the full surface — getting 32 tools when you asked for 8 should not be something you have to notice from a token bill.

The health probe answers for the profile too: `GET /mcp/health?tools=core` reports `profile` and the tools that URL would serve.

## Stateless mode

Brain runs MCP stateless: one McpServer per request, no session id. MCP clients that need long-running sessions should call once per tool use — there's no setup cost on brain's side. Stateful sessions can be added via `sessionIdGenerator` if a use case appears.

## Any other client

Everything above is the same two facts in different syntax: the URL `https://brain.inite.ai/mcp` and the header `Authorization: Bearer <api-key>`. A client that speaks remote MCP over Streamable HTTP needs nothing else — check its own docs for where those two go. A client that can only launch stdio subprocesses needs the [connector](#stdio-only-harnesses--the-initebrain-mcp-connector) below.

Clients that run OAuth themselves (Claude custom connectors, ChatGPT connectors) need only the URL: a 401 advertises the [protected-resource metadata](https://brain.inite.ai/.well-known/oauth-protected-resource), the client registers itself, and the tenant arrives in the token. See [connecting over OAuth](https://github.com/inite-ai/inite-brain-service/blob/main/docs/operations.md).
