# MCP setup

Brain ships a Streamable HTTP MCP endpoint at `/mcp/:companyId`. Each tenant has its own URL, scoped by API key.

## What you need

1. A brain **API key** (format `brain_<base64>`). Generate at `https://brain.inite.ai/admin/keys`.
2. The **companyId** the key was issued for (visible in the same screen).
3. The **MCP URL**: `https://brain.inite.ai/mcp/<companyId>`.

Brain refuses anonymous MCP traffic. There is no shared-secret mode.

## Claude Desktop

Edit `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) or `%APPDATA%\Claude\claude_desktop_config.json` (Windows):

```json
{
  "mcpServers": {
    "brain": {
      "url": "https://brain.inite.ai/mcp/<companyId>",
      "transport": "http",
      "headers": {
        "Authorization": "Bearer <api-key>"
      }
    }
  }
}
```

Quit Claude Desktop fully (not just close the window) and reopen. The brain server appears in the MCP panel — a read-only key exposes 19 tools (21 when the server runs with `FACTS_API_ENABLED=1`), a full-scope key up to 30 (see the scope matrix below).

## Cursor

`.cursor/mcp.json` in the workspace (or `~/.cursor/mcp.json` for global):

```json
{
  "mcpServers": {
    "brain": {
      "url": "https://brain.inite.ai/mcp/<companyId>",
      "transport": "http",
      "headers": {
        "Authorization": "Bearer <api-key>"
      }
    }
  }
}
```

Reload the workspace. Brain tools become available as `@brain.<tool>` in the chat panel.

## Goose

`~/.config/goose/config.yaml`:

```yaml
extensions:
  brain:
    type: streamable_http
    uri: https://brain.inite.ai/mcp/<companyId>
    headers:
      Authorization: Bearer <api-key>
    enabled: true
```

`goose session start` loads brain tools.

## n8n

In the **MCP Client** node:

- URL: `https://brain.inite.ai/mcp/<companyId>`
- Transport: HTTP (Streamable)
- Header: `Authorization: Bearer <api-key>`

Pin a credential so it's reusable across workflows.

## Hermes (Nous Research)

The [Hermes Agent](https://hermes-agent.nousresearch.com) supports remote MCP natively. Add brain under `mcp_servers` in `~/.hermes/config.yaml`:

```yaml
mcp_servers:
  brain:
    url: "https://brain.inite.ai/mcp/<companyId>"
    headers:
      Authorization: "Bearer <api-key>"
    tools:
      exclude: [forget_entity]   # optional — hide the destructive admin tool
```

Hermes discovers brain's tools at startup and registers them into its normal tool registry. The `tools.include` / `tools.exclude` filters let you expose only the surface you want the agent to see.

## stdio-only harnesses — the `@inite/brain-mcp` connector

Some harnesses can only launch **stdio** MCP servers as subprocesses and have no way to attach an `Authorization` header — [openclaw](https://github.com/openclaw/openclaw)'s MCP client is stdio-only, and so is Goose 1.x. For these, use the first-party stdio↔HTTP connector [`@inite/brain-mcp`](https://www.npmjs.com/package/@inite/brain-mcp). The harness spawns it over stdio; it transparently proxies every scoped tool to the remote endpoint, carrying the Bearer key from `env`:

```
harness ──stdio──▶ @inite/brain-mcp ──HTTP + Bearer──▶ /mcp/<companyId>
```

It is a pure passthrough — as of v0.2, `tools/list` / `tools/call` AND the resource surface (`resources/list`, `resources/templates/list`, `resources/read` — the `brain://entity/…` resources) are forwarded verbatim, so the agent sees exactly the surface the key unlocks. Sampling is bridged in reverse: brain's `sampling/createMessage` requests (from `summarize_entity` with `styleHint='client_llm'`) are forwarded to the harness so its own model writes the summary; a harness that doesn't advertise sampling gets a clean error and brain falls back to its local template. Wire it into the harness's MCP config (shown here for openclaw's `mcp.servers`):

```json
{
  "mcp": {
    "servers": {
      "brain": {
        "command": "npx",
        "args": ["-y", "@inite/brain-mcp"],
        "env": {
          "BRAIN_API_KEY": "brain_xxxxxxxx",
          "BRAIN_COMPANY_ID": "<companyId>"
        }
      }
    }
  }
}
```

| Env var | Required | Default | Notes |
| --- | --- | --- | --- |
| `BRAIN_API_KEY` | yes | — | your `brain_…` key |
| `BRAIN_COMPANY_ID` | yes\* | — | \*not needed if `BRAIN_MCP_URL` is set |
| `BRAIN_BASE_URL` | no | `https://brain.inite.ai` | point at a self-hosted brain |
| `BRAIN_MCP_URL` | no | — | full endpoint override; wins over base + company |

Auth, tenancy isolation, scopes and PII fencing stay enforced server-side from the key — the connector only carries the token. Harnesses that already speak remote MCP (Hermes, Claude Desktop, Cursor, Goose v2) should use the direct URL config above instead; the connector is only for the stdio-only case.

## Smoke test

Once connected, ask the assistant:

> List available brain tools and call `search_knowledge` with query `"hello"` limit 1.

You should see the tool count that matches the key's scopes (19 for read-only — 21 with `FACTS_API_ENABLED` — up to 30 for read+write+admin) and a `search_knowledge` result that is either empty (fresh tenant) or one hit (seed data).

If you get a 401, the bearer token is malformed or the key is invalid. If you get `400: MCP path companyId (...) does not match ApiKey companyId`, you've pasted the wrong companyId for this key.

## Scope matrix

| Scope | Tools visible |
| --- | --- |
| `brain:read` (always) | **19 read tools** — search (`search_knowledge`, `search_multi_hop`, `synthesize`, `memory_diff`, `graph_retrieve`), entity reads (`get_entity_profile`, `get_entity_timeline`, `summarize_entity`, `get_competing_facts`, `find_related_entities`, `detect_contradiction`), communities (`search_communities`, `list_communities`, `find_entity_communities`), procedural memory (`match_procedure`, `list_procedures`), source reputation (`get_source_reputation`), code memory (`why`, `recall_decisions`) — **21** when the server runs with `FACTS_API_ENABLED=1` (adds `get_fact`, `get_fact_provenance`) — plus 2 resources (`brain://entity/{id}`, `brain://entity/{id}/timeline`) |
| `brain:write` (extra) | **+8 write tools** — `record_fact`, `link_entities`, `retract_fact`, `record_procedure`, `retire_procedure`, `record_feedback`, `record_decision`, and `ingest_document` (registered only when the operator sets `DOCUMENT_INGEST_ENABLED=1`) |
| `brain:admin` (extra) | **+1** — `forget_entity`, the GDPR-grade destructive cascade |
| `brain:read_pii` (extra) | no new tools — unlocks `email` / `phone` / `dob` / `address` object values in results |
| `brain:read_media` (extra) | no new tools — media/biometric evidence access, a stricter regime than `brain:read_pii`; hosting-operator-only (env-key config, never mintable through tokens) |

Installed [Domain Packs](/en/docs/platform/domain-packs) with consented `mcpTools` add pack-declared tools (`<packId>__<tool>`) on top of these — see the [tools reference](/en/docs/mcp/tools).

A key with only `brain:read` sees 19 tools (21 with `FACTS_API_ENABLED`), not 30. That's the security invariant, not a bug.

## Stateless mode

Brain runs MCP stateless: one McpServer per request, no session id. MCP clients that need long-running sessions should call once per tool use — there's no setup cost on brain's side. Stateful sessions can be added via `sessionIdGenerator` if a use case appears.
