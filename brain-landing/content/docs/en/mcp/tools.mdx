# MCP tools reference

The server registers **28 built-in tools + 2 resources** against `McpServer({ name: 'inite-brain-service' })`, gated by scope: 19 read (`brain:read`), 8 more with `brain:write` (one of which, `ingest_document`, is registered only when `DOCUMENT_INGEST_ENABLED=1`), and 1 with `brain:admin`. Sensitive PII values require an additional `brain:read_pii` scope. On top of the built-ins, installed Domain Packs can contribute consented, namespaced tools — see the "Pack-declared tools" section below. This page documents the most commonly used tools; the full surface (communities, procedural memory, source reputation, code memory) is enumerated per scope in the [MCP setup scope matrix](/en/docs/mcp/setup) and in the repo's [`docs/api.md`](https://github.com/inite-ai/inite-brain-service/blob/main/docs/api.md).

## search_knowledge

> Semantic search over the company knowledge graph. Returns entities with their top facts and external references back to the originating verticals. Apply `asOf` for historical “what did we know on X” queries.

**Required scope:** `brain:read`

```ts
{
  query: string                  // required — natural language
  limit?: number                 // 1..100, default 10
  predicates?: string[]          // restrict to these predicates
  asOf?: string                  // ISO 8601 — bitemporal cutoff
  minConfidence?: number         // 0..1 — drop low-confidence facts
  userId?: string                // per-user memory scope (tenant-global + this user)
}
```

Pairs with the `brain-search` skill at `~/.claude/skills/brain-search/`.

## get_entity_profile

> Full profile of one entity: canonical name, type, externalRefs, and active facts. Use `externalRefs` to rehydrate fresh state from the originating vertical (e.g. via the `@inite/knowledge` client).

**Required scope:** `brain:read`

```ts
{
  entityId: string               // brain id or `vertical.id` shorthand
  asOf?: string
}
```

## get_entity_timeline

> Chronological audit of all facts brain has learned about this entity, including retracted ones. Useful for “what did we know when” investigations.

**Required scope:** `brain:read`

```ts
{
  entityId: string
  since?: string
  until?: string
}
```

Returns retracted rows too — the audit invariant.

## find_related_entities

> Entities connected to the given one via the knowledge graph. 1-hop only — call recursively for multi-hop walks.

**Required scope:** `brain:read`

```ts
{
  entityId: string
  kind?: string                  // edge filter, e.g. 'paid_for', 'mentioned_in', 'identity_of'
}
```

## record_fact

> Insert a fact about an entity. Triggers brain's conflict resolution (`INSERTED` / `SUPERSEDED` / `COMPETING` / `REJECTED`). Use sparingly from agents — most facts should come from event ingestion.

**Required scope:** `brain:write`

```ts
{
  entityRef:
    | { vertical: string, id: string }
    | { entityId: string }
  predicate: string
  object: string
  validFrom: string              // ISO 8601 — required
  validUntil?: string
  confidence?: number            // 0..1
  sourceVertical: string         // attributed source vertical
}
```

## retract_fact

> Mark a fact as no longer believed. Cascades to facts derived from this one. Does not delete; the row remains for audit.

**Required scope:** `brain:write`

```ts
{
  factId: string
  reason: string                 // required
}
```

## Pack-declared tools

A [Domain Pack](/en/docs/platform/domain-packs) may ship an `mcpTools` section — up to 8 tools contributed to the tenant's MCP surface, registered as `<packId>__<toolName>` (double underscore, the reserved separator). A pack tool is one of exactly two shapes — no third-party code ever runs inside Brain:

- **`query`** — a declarative read over the pack's OWN namespaced predicates (`search` or `facts_by_predicate` surface). Input schemas are fixed server-side; the pack picks names and descriptions, never the query shape.
- **`external`** — an HMAC-signed HTTPS proxy to a publisher-operated endpoint. The wire carries an opaque per-install `installId`, never the tenant id; responses are size-capped (64 KB), timeout-capped, and a per-endpoint circuit breaker latches after repeated failures.

Consent is explicit: installing a pack that declares `mcpTools` fails with `400` unless the install request carries `acceptMcpTools: true`, and an upgrade that changes the section re-requires it.

Everything is flag-gated by the operator:

| Flag | Default | Meaning |
| --- | --- | --- |
| `MCP_PACK_TOOLS_ENABLED` | `0` | Master switch — off means the MCP surface is exactly the built-in families |
| `MCP_PACK_QUERY_TOOLS_ENABLED` | `1` | Query tools (only reachable under the master flag) |
| `MCP_PACK_EXTERNAL_TOOLS_ENABLED` | `0` | External proxy tools |

Full reference — manifest fields, consent flow, endpoint protocol with signature verification, security model: [`docs/mcp-pack-tools.md`](https://github.com/inite-ai/inite-brain-service/blob/main/docs/mcp-pack-tools.md) in the repo.

## Common response shape

Every tool returns:

```ts
{
  content: [{ type: 'text', text: <JSON string> }],
  structuredContent: <typed object>
}
```

The `structuredContent` is what clients should parse. The `text` mirror is for clients that don't honor `structuredContent` yet.

## Errors

Tool calls return MCP error frames with these patterns:

| Pattern | Cause |
| --- | --- |
| `"scope brain:write required"` | Tool needs a scope the key lacks |
| `"MCP path companyId (...) does not match ApiKey companyId"` | URL companyId ≠ key's companyId |
| `"unknown predicate '<x>'"` | Vocabulary refused the predicate — register or use a standard one |
| `"validFrom must be ISO 8601"` | Format mismatch in `record_fact` |
